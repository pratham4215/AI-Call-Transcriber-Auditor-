# Modern Audit Experimental Runbook

## What this path does

`tools/run_modern_audit.py` uses the existing transcript parser, deterministic call-type routing, CRM snapshot loader and local LLM client. It then:
1. Sends the full transcript once to the modern 12-competency evaluator.
2. Validates model output and evidence.
3. Applies deterministic Python competency scoring.
4. Applies deterministic CRM integrity checks when supplied.
5. Adds grade, risk, compliance and human-review signals.
6. Writes a JSON audit result.

It is an experimental parallel path. It does not alter the legacy `process_one()`, scorecard workbook or Excel report.

## Example (local/offline model)

```bash
python tools/run_modern_audit.py "path/to/call.transcript.txt" \
  --crm-snapshot "path/to/crm_snapshot.json" \
  --crm-integrity-checks "path/to/crm_integrity_checks.json" \
  --backend ollama \
  --model qwen3:32b \
  --out reports/modern
```

Output:
`reports/modern/<transcript-stem>.modern-audit.json`

The CRM integrity sidecar must contain these six states:
- `booking`
- `follow_up`
- `snr`
- `escalation`
- `cre_remarks`
- `customer_remarks`

Allowed states: `pass`, `minor_defect`, `material_failure`, `not_applicable`. CRE remarks cannot be N/A. These states must be determined by trusted CRM/rule logic, not generated by the audit model.

If the sidecar is omitted, the CRM competency is model-rated provisionally and the result is routed to human review.

## Production gate

Do not enable this path for incentives until:
- per-call applicability and N/A rules are reviewed;
- CRM sidecar checks are generated from actual CRM data and deterministic rules;
- representative calls for all four call types are compared with human audits;
- score agreement, evidence quality and review rates are measured;
- a production report/export integration is approved.
